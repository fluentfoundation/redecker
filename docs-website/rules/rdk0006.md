# RDK0006 — Build folder that can never be imported

**Severity:** error · **Command:** `redecker inspect`

A package ships MSBuild logic in a build folder, and none of it is named after the package — so
NuGet never imports any of it.

## The convention

NuGet imports exactly two file names from the best-matching build folder:

```
build/<PackageId>.props
build/<PackageId>.targets
```

Anything else is only reached if one of those imports it. Ship this in a package called
`Contoso.Widgets`:

```
build/Common.targets      ← never read by anything
```

and the file is inert. Not deprecated, not warned about — simply never opened.

## Why it is worth a rule

The failure is **total and silent**. Restore succeeds. The package installs. Your build logic does
nothing at all, and there is no diagnostic anywhere, because from NuGet's point of view a package
is perfectly entitled to ship files nobody imports.

Compare that to [RDK0001](./rdk0001), where the MSBuild file *is* imported and points at something
missing. That one at least fails loudly, on one target framework. This one never says anything.

## What it checks

Every folder under `build/`, `buildTransitive/` or `buildMultiTargeting/` that contains any
`.props` or `.targets`, including framework subfolders, must contain at least one file named after
the package id.

```console
error RDK0006: build/ ships MSBuild files that can never be imported
    NuGet imports only Contoso.Widgets.props or Contoso.Widgets.targets from a build folder.
    build/ contains Common.targets, none of which matches the package id, and nothing else
    imports them. Restore succeeds and the build logic silently does nothing.
```

## What it accepts

A helper file **beside** a correctly named one is fine — that is the normal way to organise
non-trivial build logic:

```
build/Contoso.Widgets.targets   ← the entry point NuGet imports
build/Common.targets            ← imported by the above; legitimate
```

Framework subfolders are judged one at a time, since NuGet picks a folder and imports from it:

```
buildTransitive/net8.0/Contoso.Widgets.targets   ← fine
buildTransitive/net461/Helper.targets            ← reported: net461 consumers get nothing
```

Files under `tools/`, `contentFiles/` or anywhere else are ignored. Nothing imports those by
convention, so their names carry no meaning.
